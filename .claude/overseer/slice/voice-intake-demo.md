# Slice voice-intake-demo — planning artifact

## Goal
Prove that a Twilio↔Gemini Live audio bridge answers within ~3s of call answer and holds a conversation with no mid-response gap >1.5s, across 3 real PSTN test calls (scripted, 4-6 turns each) — all 3 must pass on every turn. This is the load-bearing premise the rest of a larger voice-intake-demo system depends on; if false, the bridging approach must change before anything else is built. Measurable target: all 3 real test calls pass both the answer-latency and mid-response-gap checks defined in the Exit criterion below.

## Premise verified

> **Standing rule for soxr claims (added 2026-08-25).** Three claims in this artifact about soxr's *runtime* behaviour have now failed measurement: per-chunk emission (`PR-resampler-emits-per-chunk`, falsified 2026-08-24), bit-reproducibility across instances (Premise 6, falsified 2026-08-25), and the `float32`-default failure mode (Q1's rationale, corrected 2026-08-25). Every one was stated confidently from docs or reasoning, and every one was wrong in a way only execution revealed. **No new claim about what soxr does at runtime enters this artifact without a measurement pasted alongside it.** Claims about soxr's *API surface* (signatures, parameter names) are adequately settled by reading its source; claims about what it *emits, when, and how reproducibly* are not. The failures were harmless twice and load-bearing once — that ratio is not a reason to relax the rule.

1. **VERIFIED 2026-08-23 via docs** (twilio.com/docs/voice/media-streams/websocket-messages, ai.google.dev/gemini-api/docs/live-api) — Twilio Media Streams (bidirectional) sends/receives audio as base64-encoded 8-bit μ-law mono 8kHz. Gemini Live API requires input as raw PCM16LE mono 16kHz and produces output as raw PCM16LE mono 24kHz. The bridge must transcode/resample in both directions.
2. **VERIFIED 2026-08-23 via docs** (same sources) — Gemini Live API is a persistent, stateful bidirectional WebSocket session (not request/response), supports continuous audio push and incremental streamed audio response, including barge-in/interruption events.
3. **OPEN / ACCEPTED RISK** (untested) — the actual bridge, once built, answers within ~3s and holds mid-response gaps ≤1.5s over real PSTN. This is exactly what this slice's Exit criterion (3 real test calls, all must pass) tests. Owner explicitly accepted proceeding to Phase 2 design with this unverified, in writing, via the planning session (2026-08-23).
4. **VERIFIED 2026-08-24 via docs and direct GitHub source read** (python-soxr readthedocs, github.com/dofuuz/python-soxr `src/soxr/__init__.py`, pipecat-ai docs) — `soxr.ResampleStream(in_rate, out_rate, num_channels, dtype='int16')` / `.resample_chunk(x, last=False)` is a stateful streaming resampler that keeps internal filter history across calls to the same instance, avoiding chunk-boundary clicks — the correct tool for a per-chunk calling pattern, unlike a stateless whole-array resampler.
5. **OPEN / ACCEPTED RISK** (untested, owner-ratified 2026-08-24, see `.claude/overseer/escalations.md`) — Gemini Live's intra-response audio-chunk delivery cadence is assumed small (~single-digit ms), never rivaling genuine caller-turn-boundary gaps in size — the load-bearing assumption behind the Exit criterion's "T largest gaps" turn-boundary methodology. Gemini's docs don't document chunk cadence; this is unverified. If false, the failure direction is a false NOT-PASSED (a genuine caller-turn gap could get miscounted against the 1500ms threshold), not a false PASS — the more dangerous direction (a real AI stall sneaking into the excluded set) is independently closed by the Corroboration rule regardless of this assumption's truth. Owner accepted this as an open risk rather than requiring a pre-verification spike; if it surfaces as a false NOT-PASSED during the real test calls, resolve via the Ambiguity/Corroboration rules already built into the Exit criterion, not by revisiting this premise first.

6. **VERIFIED 2026-08-25 by direct measurement** (`PR-soxr-streamed-output-not-bit-reproducible`) — two `soxr.ResampleStream` instances given byte-identical input do **not** produce byte-identical output once more than one chunk is streamed through them. Measured over 5 runs of a 6-frame inbound fixture: 735–766 of 1660 samples differ, **max 2 LSB, RMS 0.7 LSB** (~2.1e-5 of full scale, about −90 dBFS). A **single-chunk** push *is* reproducible, which is why this surfaces only in streamed fixtures. Not `.copy()`-related (tested) and not dither-by-dtype (float32 behaves the same in single-chunk form). **Consequence:** no test may compare resampled audio bit-for-bit across two instances; comparisons use Seam 2's `MAX_RMS_ERROR = 1e-3` of full scale, which still discriminates by orders of magnitude (a wrong slice, stale buffer or silence miss by ~400x). **No audio or exit-criterion risk:** the deviation is two orders of magnitude below the mu-law quantization the same signal already carries on the Twilio leg. **Falsification condition (a standing rule, not a future check):** byte-exact comparison of resampled audio across two separate `ResampleStream` instances is invalid, and **any test asserting it is wrong regardless of whether it currently passes** — a single-chunk fixture passes such an assertion, a streamed one does not, so a green suite is not evidence the assumption holds. The next person to hit a mismatch should reach for this row, not conclude the library changed.

## Seam (contract)
- Signature (pure, stateless codec functions):
  - `mulaw_decode(payload: bytes) -> bytes` — decode ITU-T G.711 μ-law → raw PCM16LE mono, 8kHz.
  - `mulaw_encode(payload: bytes) -> bytes` — raw PCM16LE mono 8kHz → ITU-T G.711 μ-law bytes, ready for base64 + Twilio media message.
- Signature (session-scoped, STATEFUL resampling components — one instance per direction, constructed once at `BridgeSession` start, never recreated per chunk):
  - **Amended 2026-08-24T20:18Z by Q12 (owner-ratified fold-in).** One class, not two: `Resampler(in_rate, out_rate)`, with `inbound_resampler()` → `Resampler(8000, 16000)` and `outbound_resampler()` → `Resampler(24000, 8000)` naming the two the bridge uses. Earlier drafts of this Seam named `InboundResampler`/`OutboundResampler`; they were structurally identical apart from rate (Critic note 2).
  - `Resampler.push(pcm16: bytes, *, last: bool = False) -> bytes`: `reject_partial_pcm16(pcm16)` → `np.frombuffer(pcm16, dtype=np.int16)` → `self._stream.resample_chunk(array, last=last)` where `self._stream = soxr.ResampleStream(in_rate, out_rate, num_channels=1, dtype='int16')` → `.tobytes()`. `dtype='int16'` is pinned explicitly (not soxr's `float32` default), so `resample_chunk` already returns int16, no separate cast needed. Returning `b""` is normal and frequent — see the empty-push contract under the handlers (Q9).
- Signature (`TimingRecorder`):
  - `TimingRecorder(clock: Callable[[], datetime], sink_path: Path)` — constructed once per `BridgeSession`, injected clock and output path. **Amended 2026-08-24T20:18Z by Q13:** creates `sink_path`'s parent directories at construction time, not at first write.
  - `record(event: str, **detail) -> None` — the ONLY public method; takes just the event name (plus optional structured detail), calls `self._clock()` internally **exactly once per call** to stamp the timestamp, and appends one JSON line `{"event": event, "timestamp": <that one stamp>.isoformat(), **detail}` to `sink_path` immediately (flushed on every call, not buffered). Callers never pass a timestamp argument; `TimingRecorder` is the sole owner of "what time is it." (Clarified 2026-08-24T20:18Z: an earlier draft wrote `self._clock().isoformat()` inline in the dict template, which read as a second invocation. One call per `record()` was always the intent per Q7, and Seam 3's sequence-valued fake clock is what enforces it.)
  - **Reserved-key guard (Q14, added 2026-08-24T20:18Z; corrected during implementation):** neither `event` nor `timestamp` can be shadowed via `**detail`, but by two different mechanisms — `record(..., timestamp=...)` reaches the guard and raises `ValueError`; `record(..., event=...)` never reaches it, because `event` is a named positional parameter and Python rejects the call with `TypeError: got multiple values for argument 'event'` first. Q14's original text said both raise `ValueError`, which was wrong for `event`. Deliberately NOT `AudioFrameError` in either case — a key collision is a defect at the call site, not a wire condition, so it must propagate past the handlers' Q6 catch rather than be dropped and logged as a recoverable frame error.
- Signature (orchestrating handlers, on `BridgeSession`):
  - `handle_twilio_frame(base64_payload: str) -> None` — base64-decode → `mulaw_decode` → `self._inbound_resampler.push(...)` → **if the push returned no bytes, return immediately: no forward, no timing event** → otherwise forward to injected `GeminiLiveSessionClient.send_audio()` → `self._timing.record("frame_forwarded_to_gemini")`.
  - `handle_gemini_chunk(pcm24k_bytes: bytes) -> None` — `self._outbound_resampler.push(...)` → **if the push returned no bytes, return immediately: no encode, no forward, no timing event** → otherwise `mulaw_encode` → base64-encode → forward to injected `TwilioMediaStreamClient.send_media()` → `self._timing.record("chunk_forwarded_to_twilio")`. (Event named for what actually happens at the point it's recorded — after resample/encode/send complete, matching the inbound handler's `X_forwarded_to_Y` naming — not "received," which would wrongly imply it marks arrival from Gemini before any local processing. Cold-reader final audit caught this naming/timing mismatch; see the Exit criterion's corrected exclusion-list reasoning below.)
  - **Empty-push contract (OWNER-RATIFIED 2026-08-24, Q9 — fold-in).** `push()` returning `b""` is normal and frequent, not an error: soxr batches internally and emits on its own schedule (measured: 41 of 50 inbound frames and 34 of 50 outbound chunks return zero samples — see `PR-resampler-emits-per-chunk`). An empty return means **nothing was sent**, so nothing may be recorded. Both handlers are conditional on non-empty bytes. The event names assert that a forward happened; firing them on a no-op would write a falsehood into the artifact the exit criterion is computed from.
  - `close() -> None` — **session teardown flush (OWNER-RATIFIED 2026-08-24, Q10 — fold-in).** Called once at call end, not per chunk and not on silence detection. Calls `self._inbound_resampler.push(b"", last=True)` and `self._outbound_resampler.push(b"", last=True)`; each flush that yields bytes is forwarded and recorded under the same event name as a normal forward, per the empty-push contract. Without this, 1060 samples (~66ms) inbound and 170 samples (~21ms) outbound stay stranded in soxr's buffer at call end — for the outbound direction that is the tail of the AI's final utterance being clipped. Resolves Critic note 1.
  - `start() -> None` — **added 2026-08-25 by Q16 (owner-ratified fold-in).** Records `self._timing.record("call_answered")`, the first event of every call. Earlier drafts said only "(Elsewhere in `BridgeSession`, at call start)" without naming a method, while the Seam's method list had no `start()`. Construction cannot be that moment: Q13 deliberately makes construction happen *before* the call is placed (so a missing sink directory fails early), so recording in `__init__` would stamp `call_answered` at object-creation time, not answer time, and silently shift the bridge-internal answer-latency diagnostic. Called once, at audible answer.
- Returns: `bytes` for codec functions and resampler `.push()` methods; `None` for handlers and `TimingRecorder.record()`.
- Errors: malformed/undersized audio payload → `mulaw_decode`/`mulaw_encode`, **`Resampler.push`**, **and `decode_base64_frame`** raise typed `AudioFrameError` (not silently swallowed). **`Resampler.push` added 2026-08-24T20:18Z by Q12 — this is a correctness fix, not tidying: see Q12's WHY. `decode_base64_frame` added 2026-08-25 by Q15 — the same correctness fix at the third and last boundary: see Q15's WHY.** `handle_twilio_frame`/`handle_gemini_chunk` each catch `AudioFrameError` at their top level, call `self._timing.record("frame_error", stage=<stage>, detail=str(exc))`, drop the corrupted frame, and return normally — the session continues rather than terminating (see Q6). **`stage` added 2026-08-25 by Q18 (owner-ratified fold-in) — `detail=str(exc)` alone is provably not diagnosable: see Q18's WHY.**
- Dependencies (injected, never imported inside the module): `TwilioMediaStreamClient`, `GeminiLiveSessionClient`, `TimingRecorder` (owns clock + sink_path internally), two `Resampler` instances — one per direction, from `inbound_resampler()` and `outbound_resampler()` — constructed once per `BridgeSession` (amended by Q12; was `InboundResampler`/`OutboundResampler`).
- Does NOT do (echoes Out of scope): caller-type routing, compliance guardrail, disclosure line, dispatch, Calendly, UK-region storage policy.

## Decisions (with WHY)

**Q1: Resampling — approach, streaming state, and exact type/call contract at the boundary.**
Chosen: `soxr.ResampleStream(in_rate, out_rate, num_channels=1, dtype='int16')` — one instance per direction, constructed once per `BridgeSession`, reused across every chunk via `.resample_chunk()`, with explicit `dtype='int16'` and explicit `np.frombuffer`/`.tobytes()` conversion at the bytes↔ndarray boundary.
WHY: verified directly against soxr's GitHub source (`dofuuz/python-soxr`, `src/soxr/__init__.py`) — the third constructor parameter is `num_channels`, not `channels`. Pinning `dtype='int16'` keeps the stream's dtype matched to the PCM16 data and removes any cast at the boundary. **Rationale corrected 2026-08-25 by measurement (`PR-soxr-int16-default-is-silent-garbage`, falsified):** an earlier draft of this line claimed the `float32` default would "misinterpret raw PCM16 samples as float amplitudes (audio garbage)." That is false. soxr type-checks the input array against the stream dtype and raises `TypeError: Input should be a np.ndarray with matching dtype for ResampleStream(float32).` on the very first `resample_chunk` call — the failure is loud and immediate, not silent corruption. **The decision is unchanged and still correct**; it was simply defended with a worse failure mode than the real one, and in the safe direction. Recorded rather than quietly edited because it is the third time in this slice that a confident claim about soxr's runtime behaviour did not survive measurement. `resample_chunk` maintains internal filter history across calls on the same instance, avoiding the chunk-boundary clicks a stateless resampler would introduce.
Rejected: `scipy.signal.resample_poly`, called per-chunk with no cross-call state (original choice). Rejected: stateless whole-array API, no cross-call filter memory — produces a discontinuity at every chunk boundary for the whole call, corrupting exactly the audio-quality signal the 3 real PSTN test calls are meant to judge.
Rejected: hand-rolled linear interpolation. Rejected: audible aliasing artifacts, more code to get right than reusing a maintained streaming resampler.

**Q2: μ-law codec — dependency vs hand-implemented?**
Chosen: hand-implement ITU-T G.711 μ-law encode/decode directly.
WHY: Python's stdlib `audioop` was **removed** in 3.13 per PEP 594 (deprecated since 3.11). **Corrected 2026-08-24T19:41Z (ADR_RATIFICATION fold-in):** an earlier draft of this line claimed verification via "`python3 -c "import audioop"` on this repo's 3.12.3 interpreter emits a DeprecationWarning." That basis is false — this repo's interpreter is **3.14.4**, where `import audioop` raises `ModuleNotFoundError`, not a DeprecationWarning, and there is no 3.12.3 interpreter on the machine. The decision is unchanged and is now stronger than "expiring": the module is already gone. The codec is ~10 lines of well-defined math, testable against the ITU-T reference table with no dependency risk. See `PR-audioop-unavailable` in the premise log for the falsification condition (pinning back to Python ≤3.12), which would change this rationale from "forced" to "deliberately chosen" without changing the decision.
Rejected: plain stdlib `audioop`. Steelman: available today, zero new code. Rejected: scheduled for removal in the next Python major version.
Rejected: an `audioop`-compatible backport (`audioop-lts`). Steelman: less code, drop-in API. Rejected: adds a dependency for something small enough to own and verify directly.

**Q3: Where timing measurement happens — inline vs separate observer?**
Chosen: separate `TimingRecorder`, called explicitly by `BridgeSession` at defined points (`call_answered`, `frame_forwarded_to_gemini`, `chunk_forwarded_to_twilio`, `frame_error`).
WHY: paranoid-SRP — audio transcoding and timing measurement are different reasons to change; separating them lets each be tested without the other.
Rejected: transport-layer packet timestamping (wiretap/proxy). Rejected: needs a standalone proxy process, disproportionate infra for a 3-call spike.

**Q4: Barge-in / interruption events from Gemini Live — handle or ignore?**
Chosen: scripted test calls avoid talking over Gemini mid-response; the bridge still subscribes to the interruption event and handles it as a no-op/log-only branch — must not crash or leave the session undefined if one arrives unprompted.
WHY: full barge-in handling is state-machine-adjacent, out of scope here — but an unhandled event type crashing the session mid-call would masquerade as a latency failure in the timing log.
Rejected: not subscribing to the interruption event at all. Rejected: if the Gemini SDK's event loop expects the event acknowledged, silently ignoring it risks undefined session behavior — worse than a cheap log-and-continue no-op.

**Q5: Timing-log output artifact format and location?**
Chosen: one JSON-lines file per test call at `.claude/artifacts/spikes/voice-intake-demo-bridge-latency-call<N>-<date>.jsonl`.
WHY: matches this project's existing spike-artifact convention; JSON-lines is trivially greppable/diffable for the Exit-criterion check without building any dashboard or log pipeline.
Rejected: stdout/console logging only. Rejected: not a durable artifact a human or the overseer can re-check later against the exit criterion.

**Q6 (OWNER-RATIFIED): AudioFrameError catch point and post-error session behavior.**
Chosen: `handle_twilio_frame` and `handle_gemini_chunk` each catch `AudioFrameError` at their top level, record a `"frame_error"` event (with detail) via `TimingRecorder`, drop the corrupted frame, and return — the session and call continue.
WHY (owner-ratified 2026-08-23, see `.claude/overseer/escalations.md`): a single recoverable event (a corrupted frame from real-world jitter/packet loss) must not crash the whole call. On real PSTN, frame corruption is realistic, not hypothetical; terminating the call on the first occurrence would burn one of only 3 scarce test-call attempts on a transient glitch. Logging the event keeps it diagnosable if a real gap violation later correlates with a `frame_error` at the same offset.
Rejected: catch, log, and terminate the call as a hard failure. Steelman: avoids a call with genuinely corrupted audio silently counting toward "3/3 calls passed." Rejected (owner's call): the cost of one transient glitch consuming a scarce test attempt outweighs the benefit, given the event is still visible in the artifact for a human to weigh.

**Q7 (OWNER-RATIFIED): who owns the clock — BridgeSession or TimingRecorder?**
Chosen: `TimingRecorder` owns the injected clock. `record(event: str, **detail) -> None` takes only the event name; it calls `self._clock()` internally. No caller ever passes a timestamp argument or calls `datetime.now()`/`time.monotonic()` itself.
WHY (owner-ratified 2026-08-23, see `.claude/overseer/escalations.md`): earlier drafts described `TimingRecorder` two contradictory ways at once — a caller-supplied-timestamp signature alongside an injected-clock dependency. The owner ratified the internal-clock reading, which also simplifies `handle_gemini_chunk`'s signature (drops a now-unneeded `received_at` parameter) — the microseconds of resampling/encoding overhead between wire arrival and the `record()` call is negligible against the 1.5s gap threshold.
Rejected: `BridgeSession` owns the one clock, computes every timestamp itself, passes it explicitly into `record(event, timestamp)`. Steelman: centralizes clock logic in one place, preserves maximum timestamp precision. Rejected (owner's call): the precision difference is immaterial at this slice's threshold scale; owner preferred co-locating the clock with the thing that writes the timestamp.

**Q8 (OWNER-RATIFIED, added 2026-08-24T19:41Z): where do the μ-law reference values in the test come from?**
Chosen: input/output pairs from the ITU-T G.711 standard table, written into the test as constants.
WHY (owner-ratified 2026-08-24, see `.claude/overseer/escalations.md`): `audioop` was removed in Python 3.13 (PEP 594); on this project's 3.14.4 interpreter it does not exist, so Q2's `audioop.ulaw2lin` is unavailable as an oracle. The constants *are* the standard; deriving expected values from our own codec would make the test tautological — it would pass on an A-law implementation, which is exactly the bug Seam 1 exists to rule out. **Note for future readers: these constants are load-bearing, not magic numbers awaiting cleanup.** Replacing them with anything computed at test time removes the test's only independent reference point.
Rejected: adding `audioop-lts` purely to generate test fixtures. Steelman: less hand-transcription, drop-in API. Rejected: reintroduces exactly the dependency Q2 deliberately removed, to serve a test rather than production.
Rejected: round-trip assertion only (`encode(decode(x)) == x`). Steelman: no transcription, no table needed. Rejected: passes on any self-consistent codec including A-law — the defect Seam 1 names first.

**Q9 (OWNER-RATIFIED, added 2026-08-24T19:41Z): what do the handlers do when `push()` returns no bytes?**
Chosen: suppress **both** the forward and the timing event. A `push()` returning `b""` means nothing was sent, so nothing is recorded.
WHY (owner-ratified 2026-08-24, see `.claude/overseer/escalations.md`): the event names — `frame_forwarded_to_gemini`, `chunk_forwarded_to_twilio` — assert that a forward happened. Firing them on a no-op writes a lie into the exact artifact the exit criterion is computed from. This was discovered by runtime probe, not design review: soxr emits nothing for 41 of 50 real-sized inbound frames and 34 of 50 outbound chunks.
Rejected: suppress the forward but still record the event. Steelman: preserves a per-frame heartbeat in the log, keeping the event stream dense and regular. Rejected: it records a forward that did not occur — and worse, phantom events *shrink* apparent gaps, so a genuine multi-second AI stall would be fragmented into sub-threshold pieces, never become a large gap, never reach the corroboration rule, and pass silently. That is the false-PASS direction this slice exists to catch.
Rejected: forward the empty payload anyway and record it. Steelman: keeps the handler branch-free. Rejected: sends nothing down a real network call while still claiming a forward — same falsehood, plus wasted round-trips.

**Q10 (OWNER-RATIFIED, added 2026-08-24T19:41Z): what triggers `push(..., last=True)`?**
Chosen: once per direction at session teardown, via `BridgeSession.close()`.
WHY (owner-ratified 2026-08-24, see `.claude/overseer/escalations.md`): soxr strands its tail until flushed — measured at 1060 samples (~66ms) inbound and 170 samples (~21ms) outbound. Outbound, that is the end of the AI's last utterance being cut off. One flush per direction at call end recovers it: the probe confirms streamed output plus `last=True` equals the whole-array reference exactly (16000 and 8000 samples). Resolves Critic note 1, which flagged this trigger as unresolved.
Rejected: `last=True` on every chunk. Steelman: never strands anything. Rejected: `last=True` finalizes the stream — it would destroy the cross-chunk filter history that Q1 exists to preserve, reintroducing the stateless bug on every frame.
Rejected: flush on silence detection. Steelman: recovers the tail mid-call, at natural turn boundaries. Rejected: needs a voice-activity detector that does not exist in this slice, and misfiring it mid-utterance would corrupt the filter state.

**Q12 (OWNER-RATIFIED, added 2026-08-24T20:18Z): resampler class shape and error surface.**
Raised by an overseer #8 finding (chat-only design) during implementation; folded in rather than routed to a new ADR — see the vehicle note at the end of this entry.

Chosen, in three parts:
1. **One `Resampler(in_rate, out_rate)`**, with `inbound_resampler()` and `outbound_resampler()` naming the two the bridge uses. Replaces `InboundResampler`/`OutboundResampler`.
2. **`Resampler.push` raises `AudioFrameError` on odd-length input**, via `reject_partial_pcm16`. Empty input stays legal.
3. **`reject_partial_pcm16` is public API of `codec.py`.**

WHY — part 2 is the substantive one and is a correctness fix, not tidying. `np.frombuffer(odd_length, dtype=np.int16)` raises a bare `ValueError`. Under the pre-amendment contract, `AudioFrameError` was scoped to `mulaw_decode`/`mulaw_encode` only, so that `ValueError` would propagate straight past `handle_gemini_chunk`'s `AudioFrameError` catch and **terminate the call on a single malformed Gemini chunk** — precisely the outcome Q6's catch-drop-continue rule exists to prevent, and precisely the scenario Q6 was ratified over (burning one of only 3 scarce PSTN test calls on a transient glitch). This is a live path, not hypothetical: the inbound leg is protected because `mulaw_decode` always emits even-length output, but `handle_gemini_chunk` pushes Gemini's bytes into the resampler with nothing in between guaranteeing an even byte count. The gap existed because Q6 was reasoned about at the codec boundary while the resampler boundary was never enumerated.

WHY — part 1 is cosmetic by comparison. The two classes differed only by rate; Critic note 2 flagged the duplication as "a cleanup opportunity, not a requirement." Collapsing them lets Seam 2's tests parametrize over direction instead of duplicating, and engages none of the no-premature-abstraction rule: no ABC, no protocol, no factory, one concrete class.

WHY — part 3 follows from part 2. The even-length rule is a property of the PCM16 representation, which `codec.py` owns. Duplicating a three-line guard across two modules is how the two drift apart later, one acquiring a better message or a corrected boundary while the other does not.

Rejected (part 1): keep two classes. Steelman: matches the pre-amendment Seam text verbatim, and the two names document direction at the call site. Rejected: the direction is already documented by `inbound_resampler()`/`outbound_resampler()`, and duplicate classes mean every Seam 2 assertion is written twice.
Rejected (part 2): leave the bare `ValueError` and widen `handle_gemini_chunk`'s catch to `(AudioFrameError, ValueError)`. Steelman: no change to the codec/resampler contract at all. Rejected: catching bare `ValueError` at a handler swallows every unrelated `ValueError` from anywhere in the call stack and relabels it a frame error — the same over-broad-catch defect Seam 4 explicitly exists to rule out.

Consequences: Seam lines for the resampler, the Dependencies list, and Seam 2's test approach all rewritten to name `Resampler`; `codec.py` gains public surface beyond the two codec functions; Critic note 2 resolved.

**Q13 (OWNER-RATIFIED, added 2026-08-24T20:18Z): does `TimingRecorder` create `sink_path`'s parent directories?**
Chosen: yes, at construction time — not lazily at first write.
WHY: the JSONL is the slice's only evidence for the exit criterion and for `PR-audio-bridge-latency`. A missing parent directory discovered at first write would destroy the entire timing log for that call, at exactly the moment nothing can be retried — after a real PSTN call has already been spent. Constructing eagerly fails early and loudly, before the call is placed, when the cost of failure is zero. The artifact path `.claude/artifacts/spikes/` does not exist in a fresh clone, so this is the default case rather than an edge case.
Rejected: create lazily on first `record()`. Steelman: no filesystem side effect from merely constructing an object. Rejected: moves the failure from setup time to mid-call, which is the one window where it is unrecoverable.
Rejected: require the caller to pre-create the directory. Steelman: keeps `TimingRecorder` free of filesystem policy. Rejected: an unenforced precondition on the component that owns the evidence file — the failure mode is silent until a real call is burned.

**Q18 (OWNER-RATIFIED, added 2026-08-25): `frame_error` must name the stage that raised.**
Raised by the owner while approving the Seam 4 behavior list, before any handler code was written.

Chosen: `record("frame_error", stage=<stage>, detail=str(exc))`, where `stage` is one of `"base64"`, `"codec"`, `"resample"`. Inbound can raise at all three; outbound at `"resample"` and `"codec"` only (base64 *encoding* cannot fail).

WHY — `detail=str(exc)` alone is not merely thin, it is ambiguous, and this was verified rather than reasoned about. `reject_partial_pcm16` is shared by `mulaw_encode` and `Resampler.push` (that sharing is Q12 part 3, and remains right). Both therefore produce the byte-identical string `'PCM16 payload must be a whole number of 2-byte samples, got 3'`. Confirmed by direct execution 2026-08-25:

```
codec mulaw_encode     -> 'PCM16 payload must be a whole number of 2-byte samples, got 3'
resampler push         -> 'PCM16 payload must be a whole number of 2-byte samples, got 3'
```

So on the outbound leg — the one Q12 identified as unprotected — a `frame_error` line written under the pre-amendment contract cannot distinguish a malformed chunk from Gemini (resampler) from a codec fault downstream of it. The timing log exists specifically for after-the-fact diagnosis of a call that cannot be replayed; a line saying only "a frame was dropped" fails at the one job it has, and fails it exactly in the case where something already went wrong. This is the Q9/Q14 judgment a third time: the artifact must not record something that reads plausible while being unusable.

Implementation constraint: the stage is tracked in a local reassigned as the flow advances, with **one** top-level `except AudioFrameError` retained. Per-step `try` blocks would tag stages equally well but would reintroduce the narrow catch that behavior T4 exists to rule out — and a catch narrower than it looks is this slice's repeat defect (`struct.error` at the codec, `ValueError` from `np.frombuffer` at Q12, `binascii.Error` at Q15).

Rejected: a `stage` attribute set on `AudioFrameError` at each raise site. Steelman: intrinsic to the error, impossible for a flow to mislabel. Rejected: `reject_partial_pcm16` is shared, so the raise site provably does not know which stage called it — that is the whole finding.
Rejected: distinct exception subclasses per stage. Steelman: type-dispatchable, no string values. Rejected: three new classes to carry one string, and the handler's single catch would have to name all of them — new abstraction where a field does.

**Correction during implementation (2026-08-25, owner-ratified same-turn fold-in per the standing rule).** Q18 as first written said "Inbound can raise at all three; outbound at `resample` and `codec` only" — five reachable (stage, direction) combinations. Reading our own source, **two of the five are structurally unreachable**, leaving three: inbound `base64`, inbound `codec`, outbound `resample`.

- **Inbound `resample` is unreachable.** `mulaw_decode` packs exactly one 16-bit sample per input byte (`codec.py`, `struct.pack(f"<{len(samples)}h", ...)`), so its output length is always even. `reject_partial_pcm16` — the only `AudioFrameError` source in `Resampler.push` — therefore cannot fire on the inbound leg.
- **Outbound `codec` is unreachable.** soxr's int16 output `.tobytes()` is always even-length, and Q9's empty guard has already returned before `mulaw_encode` is called, so neither of that function's two guards (`_reject_empty`, `reject_partial_pcm16`) can fire on the outbound leg.

Chosen: **keep both stage branches, test only the three reachable ones, and record here why the other two are inert** — the same treatment Q14 gave the unreachable `event` key.

**This claim's basis, and how it differs from Q14's.** Q14's `event` branch is unreachable because *Python's own argument binding* forbids the call — a guarantee of the language, which our code cannot weaken. These two are unreachable because of *how our own pipeline is currently ordered* — a guarantee only for as long as nobody reorders it. Reorder the inbound flow, or widen a signature so `Resampler.push` can see odd bytes on the inbound leg, and the branch becomes live with nothing to catch it. **Weaker claim, same conclusion, different reason** — and that difference is the whole point of writing it down: the branch must not be pruned as dead code on the strength of a property that a refactor can silently remove.

Note on evidence standard: this is arithmetic over our own `struct.pack` call, not a claim about soxr's runtime behaviour, so the standing soxr measurement rule at the top of this artifact does not apply. It is verifiable by reading `codec.py`.

**Q19 (OWNER-RATIFIED, added 2026-08-25): what happens to the timing log if teardown itself raises?**
Chosen: a non-`AudioFrameError` exception from a flush **propagates** out of `close()`; the log keeps every line written before it, each independently valid JSON. Asserted by behavior C3.

WHY (owner-directed): the JSONL is the sole evidence for the exit criterion and for `PR-audio-bridge-latency`. Rejected: it would have to catch broadly (the error is a `RuntimeError`, not an `AudioFrameError`), which is the over-broad catch Q12 and Q15 both rejected — and it would hide a genuine double-teardown defect rather than surface it.

## Hardest seams (test-confidence points — distinct from the contract Seam above)

- **Seam 1: μ-law codec correctness (law-in-use, not lossy round-trip)** — test approach: test `mulaw_decode`/`mulaw_encode` against fixed ITU-T G.711 reference-table entries (e.g. 0xFF decodes to near-zero, 0x00 decodes to the max-negative excursion −32124), asserting exact/near-exact match against the standard, not against each other. **Provenance corrected 2026-08-24T19:41Z (same fold-in as Q2/Q8):** an earlier draft cited these as "verified via `audioop.ulaw2lin` reference decode." That check cannot have been run on this machine — `audioop` is absent on Python 3.14.4. The values themselves are unchanged and correct per the ITU-T G.711 table; only the false provenance is removed. Per Q8, transcribe them from the standard, not from any runtime oracle. Rules out: (a) accidentally implementing A-law instead of μ-law — a same-shape, different-values bug a lossy round-trip test would NOT catch; (b) sign-bit/byte-order errors a silence-only smoke test would miss.

- **Seam 2: Resampler statefulness across chunk boundaries** (the seam that drove most of Phase 2's design iteration) — test approach: generate a continuous test tone at the input rate, split it into several small chunks sized like real Twilio frames, push them sequentially through the SAME `Resampler` instance (amended by Q12; was `InboundResampler`) via repeated `.push()` calls, and diff the concatenated output against resampling the whole tone in one call. Separately assert no artificial discontinuity at a chunk boundary. Rules out: constructing a fresh `soxr.ResampleStream` per call (silently reintroducing the stateless bug found and fixed during design), and any test that only ever feeds one whole-buffer chunk (passes even on a broken per-chunk implementation).

  **Amended 2026-08-24 (owner-directed, same fold-in as Q9/Q10).** This test was written before the empty-return behaviour was known, and must now also assert it explicitly. Three additions:
  (a) **Empty returns are expected and legal** — assert that pushing real-sized frames produces `b""` for some of them and non-empty bytes for others, rather than asserting every push yields audio. Measured shape: 41 of 50 inbound frames empty, the rest 1660 samples.
  (b) **Nothing is lost** — assert that the concatenation of every streamed push *plus* the `last=True` flush equals the whole-array reference exactly (16000 samples for the 8k→16k case), not merely approximately. **Clarified 2026-08-25:** "exactly" here means the **sample count** is exact — which is what `tests/test_resampler.py` asserts (`(len(streamed) + len(flushed)) // 2 == len(expected)`). Sample *values* are compared at `MAX_RMS_ERROR`, and must be: per Premise 6, streamed soxr output is not bit-reproducible across instances. The existing Seam 2 tests were already written this way; only the wording here invited a bit-exact misreading. This is what proves the empty returns are batching rather than data loss.
  (c) **The stateless bug produces silence, not noise** — assert that a fresh instance per chunk yields **zero total samples**, and that the correct pattern does not. This is the reason (a) cannot be a bare "some pushes are empty" check: a fresh-instance-per-chunk bug returns empty on *every* push, and empty pushes are now suppressed at the handler, so a fully broken bridge forwards nothing while emitting no events at all — indistinguishable from a healthy idle line by the timing artifact alone. This test is the only thing that separates those two states.

- **Seam 3: TimingRecorder event-stream integrity** — Phase 2's `TimingRecorder` contract is `record(event, **detail) -> None`, a write sink with no live query method; gap analysis is offline analysis of the JSONL, not a tested unit of this slice. Assertions are made by re-reading the actual JSONL file from disk after the calls (never an in-memory buffer). Rules out: buffer-then-flush-on-untested-close (silent data loss); real wall-clock leakage; swapped/generic event names; unspecified timestamp serialization; and silently dropping `**detail`.

- **Seam 4: `BridgeSession` orchestration — base64 decode, session start, both directional handlers, and teardown flush** (includes Q6's catch-drop-continue policy, which is one part of it, not the whole) — **renamed 2026-08-26 by Q21; was "AudioFrameError resilience".** The old name predates the behavior list: it was written during planning, when the seam was scoped to Q6's error path alone, and the ratified 16-behavior list below then grew it to cover `decode_base64_frame` (Q15), `start()` (Q16) and `close()` (Q10, Q19) as well. ## Exit criterion

The slice is done when BOTH of the following hold:

**1. Unit test suite (Phase 3 seams) — every ratified behavior covered, and nothing beyond.** Amended 2026-08-26 by Q21. The criterion is a **property over the behavior lists**, not a list of test names:

> For each of the four seams, **every behavior in that seam's ratified behavior list has a passing test, and the seam's test file contains no test that does not trace to an entry in that list.** Both directions are required: the first catches a dropped behavior, the second catches a test that drifted in without ratification.

Seam → file: Seam 1 → `tests/test_codec.py`; Seam 2 → `tests/test_resampler.py`; Seam 3 → `tests/test_timing.py`; Seam 4 → `tests/test_session.py`. Each test's docstring opens with its behavior ID, so the mapping is checkable by reading the file.

**Why not test names.** The pre-amendment version of this criterion named four literal test functions, and three of them did not exist — the codec and timing ones only as prefixed variants, `test_audio_frame_error_resilience` not at all. Those names were written during planning as *seam labels*, before any test existed, and were never ratified as names; the per-behavior split that replaced them **was** ratified (Seam 2's amendment, Seam 4's 16-behavior list). Pinning the criterion to names — even to name *prefixes* — reproduces the same defect one degree weaker: the next rename or split breaks it again. Pointing at the behavior lists makes the criterion track the thing that was actually ratified.

Greppable prefixes, as a **convenience for finding the tests, not as the proof**: `test_mulaw_codec_reference_table*`, `test_resampler_statefulness_across_chunks`, `test_timing_recorder_event_stream_integrity*`. Seam 4's 16 are the `D*`/`S1`/`T*`/`G*`/`C*` behaviors in `tests/test_session.py`.

**Precondition, unmet as of 2026-08-26 — this criterion is only as good as the lists it points at.** Only Seam 4's behavior list is written into this artifact. Seams 1-3's lists were approved in chat and exist nowhere but the tests' own docstrings, which makes checking them against the tests circular. **Concrete evidence that this is not a formality:** `tests/test_resampler.py` numbers its behaviors B1, B2, B3, B4, B5, **B7** — there is no B6, and no record anywhere of what B6 was or whether it was cut deliberately. Under this criterion that is exactly the finding it should produce, and it cannot be resolved by reading the tests: reconstructing a ratified list from the code it is supposed to check is the tautology Q8 rejected. See "Open items requiring human decision".

**2. Real-environment smoke — 3 real PSTN test calls, ALL must pass.** Each call is placed to the deployed bridge, follows a scripted 4-6 turn conversation, and produces one artifact at `.claude/artifacts/spikes/voice-intake-demo-bridge-latency-call<N>-<date>.jsonl` plus a companion `...turnlog.txt`.

From each pair of artifacts, both of the following must hold:

- **Answer latency (audible, tester-measured — the deciding number, not a bridge-internal proxy):** the tester's manual timing log starts a stopwatch the instant the call audibly connects (ringback stops/pickup) and stops it the instant they hear the AI's greeting begin. This audible figure — not the JSONL's `call_answered`→first-`chunk_forwarded_to_twilio` delta — decides the ≤3000ms PASS/FAIL. **Corrected exclusion (cold-reader final audit finding):** `chunk_forwarded_to_twilio` fires only *after* local resample/encode/Twilio-send-call processing completes (see Seam), so the bridge-internal delta already includes that local processing time — it excludes only the PSTN transit + phone-speaker leg after the bridge hands the chunk to Twilio. That excluded leg is itself exactly the risk the ~3s threshold exists to catch (a call could report a fast bridge-internal number while a real broker, waiting on PSTN + speaker delay on top of it, experiences ≥3s) — so the audible figure remains the correct deciding number, just for the accurate reason (PSTN+speaker only, not "encode→resample→Twilio send" as an earlier draft incorrectly claimed was excluded). The JSONL delta is retained only as a secondary bridge-side diagnostic. The `.turnlog.txt` file's required first line, `answer_latency_s: <value>`, is the one written, auditable location for the deciding number — without it the file is incomplete and the call cannot be marked DONE.

- **Mid-response gap:** compute the gap between every consecutive pair of `chunk_forwarded_to_twilio` timestamps. `frame_forwarded_to_gemini` is NOT usable as a turn-boundary signal (Twilio forwards inbound audio continuously, ~20ms cadence, regardless of caller speech — verified against Twilio's docs). Instead: the AI is configured to greet proactively/unprompted on connection (required by the goal itself — "answers within ~3s of call answer," not "of the caller's first line"). A scripted call with T caller turns (4-6) produces T+1 AI-response episodes and therefore T inter-episode gaps. Take the **T largest gaps** as candidate excluded turn-boundaries, matched to the script in chronological order; every other (smaller) gap counts against the ≤1500ms threshold. (Note: because `chunk_forwarded_to_twilio` fires post-processing, these gaps include local resample/encode/send time alongside Gemini's own inter-chunk cadence. **Quantization floor — OWNER-RATIFIED 2026-08-24, Q11 fold-in.** An earlier draft called this "single-digit milliseconds per chunk"; the runtime probe falsified that. soxr does not emit per chunk — it batches, producing bursts of ~61ms outbound (489-490 samples at 8kHz, roughly every third chunk) rather than a continuous stream. Q9's empty-push suppression makes every recorded event a real forward again, so the gaps between consecutive events are genuine; but the *resolution* of the method is now quantized at roughly one burst interval. **Consequence, stated rather than assumed: a genuine stall shorter than one burst interval (~61ms) is invisible to this method.** Against a 1500ms threshold that is a ~24x margin — comfortably within tolerance, and the methodology is unchanged — but it is a real blind spot and is written down here rather than left implicit. This "T largest gaps" methodology itself rests on Premise 5 — OPEN/ACCEPTED RISK — that Gemini's intra-response chunk cadence never rivals genuine caller-turn gaps in size; if that premise is false, the failure mode is a false NOT-PASSED, caught and resolved via the Ambiguity/Corroboration rules below, not a silent false PASS.)
  - **Corroboration rule:** any excluded gap that individually exceeds 1500ms MUST be corroborated before being excluded, confirming the caller was genuinely speaking during that interval rather than the AI silently stalling — otherwise the call is marked NOT PASSED. (Excluded gaps ≤1500ms need no corroboration, since they couldn't have failed the threshold regardless.) This closes the failure mode where a genuine mid-response stall — by construction one of the largest gaps in the call — could otherwise be swept into the excluded set purely for being large.
  - **Corroboration mechanism:** the tester's manual timing log, zeroed to hearing the AI's greeting begin (the same real-world moment as the first `chunk_forwarded_to_twilio` event, offset by the same constant — not zero — transit delay that cancels in relative comparisons). The tester logs elapsed time at which they begin speaking each subsequent scripted turn. A candidate excluded gap is corroborated if its greeting-relative start offset falls within **±1000ms** of the tester's logged greeting-relative start-time for that turn; outside that window, corroboration fails and the call is NOT PASSED.
  - **Ambiguity rule:** if the T-largest/rest split is itself unclear (a gap near the cutoff is close in magnitude to its neighbors), the reviewer resolves it via the same corroboration, or the call is marked NOT PASSED — never a guess.

**All 3 calls must satisfy both conditions on every turn.** A single violation anywhere falsifies Premise 3 — the response is architectural rework, not a retry. This analysis is done manually against the known call script, per the "Manual on purpose" section of `.claude/architecture/mvp/voice-intake-demo.md` — this is this project's first slice, so that MVP doc (not a cross-slice precedent) is the actual source of the manual-review approach.

**What proves DONE:** **(amended 2026-08-26 by Q21)** the behavior-coverage property in item 1 shown to hold — for each seam, every ratified behavior mapped to a passing test and no unmapped test in its file, with the suite run visible in the transcript — AND the 3 JSONL + `.turnlog.txt` artifact pairs named explicitly with the audible answer-latency (deciding), bridge-internal JSONL delta (diagnostic), and mid-response-gap numbers read out per call — not a generic "the calls worked."
