# Slice voice-intake-demo — planning artifact

## Goal
Prove that a Twilio↔Gemini Live audio bridge answers within ~3s of call answer and holds a conversation with no mid-response gap >1.5s, across 3 real PSTN test calls (scripted, 4-6 turns each) — all 3 must pass on every turn. This is the load-bearing premise the rest of a larger voice-intake-demo system depends on; if false, the bridging approach must change before anything else is built. Measurable target: all 3 real test calls pass both the answer-latency and mid-response-gap checks defined in the Exit criterion below.

## Premise verified
1. **VERIFIED 2026-08-23 via docs** (twilio.com/docs/voice/media-streams/websocket-messages, ai.google.dev/gemini-api/docs/live-api) — Twilio Media Streams (bidirectional) sends/receives audio as base64-encoded 8-bit μ-law mono 8kHz. Gemini Live API requires input as raw PCM16LE mono 16kHz and produces output as raw PCM16LE mono 24kHz. The bridge must transcode/resample in both directions.
2. **VERIFIED 2026-08-23 via docs** (same sources) — Gemini Live API is a persistent, stateful bidirectional WebSocket session (not request/response), supports continuous audio push and incremental streamed audio response, including barge-in/interruption events.
3. **OPEN / ACCEPTED RISK** (untested) — the actual bridge, once built, answers within ~3s and holds mid-response gaps ≤1.5s over real PSTN. This is exactly what this slice's Exit criterion (3 real test calls, all must pass) tests. Owner explicitly accepted proceeding to Phase 2 design with this unverified, in writing, via the planning session (2026-08-23).
4. **VERIFIED 2026-08-24 via docs and direct GitHub source read** (python-soxr readthedocs, github.com/dofuuz/python-soxr `src/soxr/__init__.py`, pipecat-ai docs) — `soxr.ResampleStream(in_rate, out_rate, num_channels, dtype='int16')` / `.resample_chunk(x, last=False)` is a stateful streaming resampler that keeps internal filter history across calls to the same instance, avoiding chunk-boundary clicks — the correct tool for a per-chunk calling pattern, unlike a stateless whole-array resampler.
5. **OPEN / ACCEPTED RISK** (untested, owner-ratified 2026-08-24, see `.claude/overseer/escalations.md`) — Gemini Live's intra-response audio-chunk delivery cadence is assumed small (~single-digit ms), never rivaling genuine caller-turn-boundary gaps in size — the load-bearing assumption behind the Exit criterion's "T largest gaps" turn-boundary methodology. Gemini's docs don't document chunk cadence; this is unverified. If false, the failure direction is a false NOT-PASSED (a genuine caller-turn gap could get miscounted against the 1500ms threshold), not a false PASS — the more dangerous direction (a real AI stall sneaking into the excluded set) is independently closed by the Corroboration rule regardless of this assumption's truth. Owner accepted this as an open risk rather than requiring a pre-verification spike; if it surfaces as a false NOT-PASSED during the real test calls, resolve via the Ambiguity/Corroboration rules already built into the Exit criterion, not by revisiting this premise first.

## Seam (contract)
- Signature (pure, stateless codec functions):
  - `mulaw_decode(payload: bytes) -> bytes` — decode ITU-T G.711 μ-law → raw PCM16LE mono, 8kHz.
  - `mulaw_encode(payload: bytes) -> bytes` — raw PCM16LE mono 8kHz → ITU-T G.711 μ-law bytes, ready for base64 + Twilio media message.
- Signature (session-scoped, STATEFUL resampling components — one instance per direction, constructed once at `BridgeSession` start, never recreated per chunk):
  - `InboundResampler.push(pcm16_8k: bytes, *, last: bool = False) -> bytes`: `np.frombuffer(pcm16_8k, dtype=np.int16)` → `self._stream.resample_chunk(array, last=last)` where `self._stream = soxr.ResampleStream(8000, 16000, num_channels=1, dtype='int16')` → `.tobytes()`. `dtype='int16'` is pinned explicitly (not soxr's `float32` default), so `resample_chunk` already returns int16, no separate cast needed.
  - `OutboundResampler.push(pcm16_24k: bytes, *, last: bool = False) -> bytes` — identical shape, `soxr.ResampleStream(24000, 8000, num_channels=1, dtype='int16')`.
- Signature (`TimingRecorder`):
  - `TimingRecorder(clock: Callable[[], datetime], sink_path: Path)` — constructed once per `BridgeSession`, injected clock and output path.
  - `record(event: str, **detail) -> None` — the ONLY public method; takes just the event name (plus optional structured detail), calls `self._clock()` internally to stamp the timestamp, and appends one JSON line `{"event": event, "timestamp": self._clock().isoformat(), **detail}` to `sink_path` immediately (flushed on every call, not buffered). Callers never pass a timestamp argument; `TimingRecorder` is the sole owner of "what time is it."
- Signature (orchestrating handlers, on `BridgeSession`):
  - `handle_twilio_frame(base64_payload: str) -> None` — base64-decode → `mulaw_decode` → `self._inbound_resampler.push(...)` → forward to injected `GeminiLiveSessionClient.send_audio()` → `self._timing.record("frame_forwarded_to_gemini")`.
  - `handle_gemini_chunk(pcm24k_bytes: bytes) -> None` — `self._outbound_resampler.push(...)` → `mulaw_encode` → base64-encode → forward to injected `TwilioMediaStreamClient.send_media()` → `self._timing.record("chunk_forwarded_to_twilio")`. (Event named for what actually happens at the point it's recorded — after resample/encode/send complete, matching the inbound handler's `X_forwarded_to_Y` naming — not "received," which would wrongly imply it marks arrival from Gemini before any local processing. Cold-reader final audit caught this naming/timing mismatch; see the Exit criterion's corrected exclusion-list reasoning below.)
  - (Elsewhere in `BridgeSession`, at call start) `self._timing.record("call_answered")` — the first event of every call.
- Returns: `bytes` for codec functions and resampler `.push()` methods; `None` for handlers and `TimingRecorder.record()`.
- Errors: malformed/undersized audio payload → `mulaw_decode`/`mulaw_encode` raise typed `AudioFrameError` (not silently swallowed). `handle_twilio_frame`/`handle_gemini_chunk` each catch `AudioFrameError` at their top level, call `self._timing.record("frame_error", detail=str(exc))`, drop the corrupted frame, and return normally — the session continues rather than terminating (see Q6).
- Dependencies (injected, never imported inside the module): `TwilioMediaStreamClient`, `GeminiLiveSessionClient`, `TimingRecorder` (owns clock + sink_path internally), `InboundResampler`/`OutboundResampler` instances (constructed once per `BridgeSession`).
- Does NOT do (echoes Out of scope): caller-type routing, compliance guardrail, disclosure line, dispatch, Calendly, UK-region storage policy.

## Decisions (with WHY)

**Q1: Resampling — approach, streaming state, and exact type/call contract at the boundary.**
Chosen: `soxr.ResampleStream(in_rate, out_rate, num_channels=1, dtype='int16')` — one instance per direction, constructed once per `BridgeSession`, reused across every chunk via `.resample_chunk()`, with explicit `dtype='int16'` and explicit `np.frombuffer`/`.tobytes()` conversion at the bytes↔ndarray boundary.
WHY: verified directly against soxr's GitHub source (`dofuuz/python-soxr`, `src/soxr/__init__.py`) — the third constructor parameter is `num_channels`, not `channels`. Pinning `dtype='int16'` avoids soxr's `float32` default misinterpreting raw PCM16 samples as float amplitudes (audio garbage). `resample_chunk` maintains internal filter history across calls on the same instance, avoiding the chunk-boundary clicks a stateless resampler would introduce.
Rejected: `scipy.signal.resample_poly`, called per-chunk with no cross-call state (original choice). Rejected: stateless whole-array API, no cross-call filter memory — produces a discontinuity at every chunk boundary for the whole call, corrupting exactly the audio-quality signal the 3 real PSTN test calls are meant to judge.
Rejected: hand-rolled linear interpolation. Rejected: audible aliasing artifacts, more code to get right than reusing a maintained streaming resampler.

**Q2: μ-law codec — dependency vs hand-implemented?**
Chosen: hand-implement ITU-T G.711 μ-law encode/decode directly.
WHY: Python's stdlib `audioop` is deprecated and removed as of 3.13 (verified: `python3 -c "import audioop"` on this repo's 3.12.3 interpreter emits a DeprecationWarning) — an expiring premise. The codec is ~10 lines of well-defined math, testable against the ITU-T reference table with no dependency risk.
Rejected: plain stdlib `audioop`. Steelman: available today, zero new code. Rejected: scheduled for removal in the next Python major version.
Rejected: an `audioop`-compatible backport (`audioop-lts`). Steelman: less code, drop-in API. Rejected: adds a dependency for something small enough to own and verify directly.

**Q3: Where timing measurement happens — inline vs separate observer?**
Chosen: separate `TimingRecorder`, called explicitly by `BridgeSession` at defined points (`call_answered`, `frame_forwarded_to_gemini`, `chunk_forwarded_to_twilio`, `frame_error`).
WHY: paranoid-SRP — audio transcoding and timing measurement are different reasons to change; separating them lets each be tested without the other.
Rejected: transport-layer packet timestamping (wiretap/proxy). Rejected: needs a standalone proxy process, disproportionate infra for a 3-call spike.

**Q4: Barge-in / interruption events from Gemini Live — handle or ignore?**
Chosen: scripted test calls avoid talking over Gemini mid-response; the bridge still subscribes to the interruption event and handles it as a no-op/log-only branch — must not crash or leave the session undefined if one arrives unprompted.
WHY: full barge-in handling is state-machine-adjacent, out of scope here — but an unhandled event type crashing the session mid-call would masquerade as a latency failure in the timing log.
Rejected: not subscribing to the interruption event at all. Rejected: if the Gemini SDK's event loop expects the event acknowledged, silently ignoring it risks undefined session behavior — worse than a cheap log-and-continue no-op.

**Q5: Timing-log output artifact format and location?**
Chosen: one JSON-lines file per test call at `.claude/artifacts/spikes/voice-intake-demo-bridge-latency-call<N>-<date>.jsonl`.
WHY: matches this project's existing spike-artifact convention; JSON-lines is trivially greppable/diffable for the Exit-criterion check without building any dashboard or log pipeline.
Rejected: stdout/console logging only. Rejected: not a durable artifact a human or the overseer can re-check later against the exit criterion.

**Q6 (OWNER-RATIFIED): AudioFrameError catch point and post-error session behavior.**
Chosen: `handle_twilio_frame` and `handle_gemini_chunk` each catch `AudioFrameError` at their top level, record a `"frame_error"` event (with detail) via `TimingRecorder`, drop the corrupted frame, and return — the session and call continue.
WHY (owner-ratified 2026-08-23, see `.claude/overseer/escalations.md`): a single recoverable event (a corrupted frame from real-world jitter/packet loss) must not crash the whole call. On real PSTN, frame corruption is realistic, not hypothetical; terminating the call on the first occurrence would burn one of only 3 scarce test-call attempts on a transient glitch. Logging the event keeps it diagnosable if a real gap violation later correlates with a `frame_error` at the same offset.
Rejected: catch, log, and terminate the call as a hard failure. Steelman: avoids a call with genuinely corrupted audio silently counting toward "3/3 calls passed." Rejected (owner's call): the cost of one transient glitch consuming a scarce test attempt outweighs the benefit, given the event is still visible in the artifact for a human to weigh.

**Q7 (OWNER-RATIFIED): who owns the clock — BridgeSession or TimingRecorder?**
Chosen: `TimingRecorder` owns the injected clock. `record(event: str, **detail) -> None` takes only the event name; it calls `self._clock()` internally. No caller ever passes a timestamp argument or calls `datetime.now()`/`time.monotonic()` itself.
WHY (owner-ratified 2026-08-23, see `.claude/overseer/escalations.md`): earlier drafts described `TimingRecorder` two contradictory ways at once — a caller-supplied-timestamp signature alongside an injected-clock dependency. The owner ratified the internal-clock reading, which also simplifies `handle_gemini_chunk`'s signature (drops a now-unneeded `received_at` parameter) — the microseconds of resampling/encoding overhead between wire arrival and the `record()` call is negligible against the 1.5s gap threshold.
Rejected: `BridgeSession` owns the one clock, computes every timestamp itself, passes it explicitly into `record(event, timestamp)`. Steelman: centralizes clock logic in one place, preserves maximum timestamp precision. Rejected (owner's call): the precision difference is immaterial at this slice's threshold scale; owner preferred co-locating the clock with the thing that writes the timestamp.

## Hardest seams (test-confidence points — distinct from the contract Seam above)

- **Seam 1: μ-law codec correctness (law-in-use, not lossy round-trip)** — test approach: test `mulaw_decode`/`mulaw_encode` against fixed ITU-T G.711 reference-table entries (e.g. 0xFF decodes near-zero/silence, 0x00 decodes to max-negative excursion — verified 2026-08-24 via `audioop.ulaw2lin` reference decode), asserting exact/near-exact match against the standard, not against each other. Rules out: (a) accidentally implementing A-law instead of μ-law — a same-shape, different-values bug a lossy round-trip test would NOT catch; (b) sign-bit/byte-order errors a silence-only smoke test would miss.

- **Seam 2: Resampler statefulness across chunk boundaries** (the seam that drove most of Phase 2's design iteration) — test approach: generate a continuous test tone at the input rate, split it into several small chunks sized like real Twilio frames, push them sequentially through the SAME `InboundResampler` instance via repeated `.push()` calls, and diff the concatenated output against resampling the whole tone in one call. Separately assert no artificial discontinuity at a chunk boundary. Rules out: constructing a fresh `soxr.ResampleStream` per call (silently reintroducing the stateless bug found and fixed during design), and any test that only ever feeds one whole-buffer chunk (passes even on a broken per-chunk implementation).

- **Seam 3: TimingRecorder event-stream integrity** — Phase 2's `TimingRecorder` contract is `record(event, **detail) -> None`, a write sink with no live query method; gap analysis is offline analysis of the JSONL, not a tested unit of this slice. Test approach: construct `TimingRecorder` with an injected fake clock (a stub returning a pre-scripted sequence of known, distinguishable-from-wall-clock `datetime` values) and a real temp file path. Call `record()` several times with distinct known event names (mixing `frame_forwarded_to_gemini`, `chunk_forwarded_to_twilio`, and `frame_error`), including one `frame_error` call with `detail="simulated decode error"`. Assertions are made by re-reading the actual JSONL file from disk after the calls (never an in-memory buffer). Assert: (a) line count/order matches calls exactly; (b) each line's `event` field matches exactly; (c) each line's `timestamp`, parsed via `datetime.fromisoformat()`, matches the fake clock's corresponding value; (d) the `frame_error` line's `detail` field matches exactly. Rules out: buffer-then-flush-on-untested-close (silent data loss); real wall-clock leakage; swapped/generic event names; unspecified timestamp serialization; and silently dropping `**detail`.

- **Seam 4: AudioFrameError resilience (Q6's catch-drop-continue policy)** — test approach: feed a malformed/undersized payload into `handle_twilio_frame`, assert (a) no exception propagates past the handler, (b) `TimingRecorder` receives exactly one `"frame_error"` record, (c) immediately feed a valid frame and assert it resamples/forwards correctly — proving the resampler's internal state wasn't corrupted by the aborted frame. Rules out: catching too broadly (silently swallowing subsequent valid frames) and catching while leaving the resampler's internal soxr state half-consumed.

## Exit criterion

The slice is done when BOTH of the following hold:

**1. Unit test suite (Phase 3 seams) — all green:** `test_mulaw_codec_reference_table`, `test_resampler_statefulness_across_chunks`, `test_timing_recorder_event_stream_integrity`, `test_audio_frame_error_resilience`.

**2. Real-environment smoke — 3 real PSTN test calls, ALL must pass.** Each call is placed to the deployed bridge, follows a scripted 4-6 turn conversation, and produces one artifact at `.claude/artifacts/spikes/voice-intake-demo-bridge-latency-call<N>-<date>.jsonl` plus a companion `...turnlog.txt`.

From each pair of artifacts, both of the following must hold:

- **Answer latency (audible, tester-measured — the deciding number, not a bridge-internal proxy):** the tester's manual timing log starts a stopwatch the instant the call audibly connects (ringback stops/pickup) and stops it the instant they hear the AI's greeting begin. This audible figure — not the JSONL's `call_answered`→first-`chunk_forwarded_to_twilio` delta — decides the ≤3000ms PASS/FAIL. **Corrected exclusion (cold-reader final audit finding):** `chunk_forwarded_to_twilio` fires only *after* local resample/encode/Twilio-send-call processing completes (see Seam), so the bridge-internal delta already includes that local processing time — it excludes only the PSTN transit + phone-speaker leg after the bridge hands the chunk to Twilio. That excluded leg is itself exactly the risk the ~3s threshold exists to catch (a call could report a fast bridge-internal number while a real broker, waiting on PSTN + speaker delay on top of it, experiences ≥3s) — so the audible figure remains the correct deciding number, just for the accurate reason (PSTN+speaker only, not "encode→resample→Twilio send" as an earlier draft incorrectly claimed was excluded). The JSONL delta is retained only as a secondary bridge-side diagnostic. The `.turnlog.txt` file's required first line, `answer_latency_s: <value>`, is the one written, auditable location for the deciding number — without it the file is incomplete and the call cannot be marked DONE.

- **Mid-response gap:** compute the gap between every consecutive pair of `chunk_forwarded_to_twilio` timestamps. `frame_forwarded_to_gemini` is NOT usable as a turn-boundary signal (Twilio forwards inbound audio continuously, ~20ms cadence, regardless of caller speech — verified against Twilio's docs). Instead: the AI is configured to greet proactively/unprompted on connection (required by the goal itself — "answers within ~3s of call answer," not "of the caller's first line"). A scripted call with T caller turns (4-6) produces T+1 AI-response episodes and therefore T inter-episode gaps. Take the **T largest gaps** as candidate excluded turn-boundaries, matched to the script in chronological order; every other (smaller) gap counts against the ≤1500ms threshold. (Note: because `chunk_forwarded_to_twilio` fires post-processing, these gaps include local resample/encode/send time alongside Gemini's own inter-chunk cadence — expected to be single-digit milliseconds per chunk, negligible against the 1500ms threshold. This "T largest gaps" methodology itself rests on Premise 5 — OPEN/ACCEPTED RISK — that Gemini's intra-response chunk cadence never rivals genuine caller-turn gaps in size; if that premise is false, the failure mode is a false NOT-PASSED, caught and resolved via the Ambiguity/Corroboration rules below, not a silent false PASS.)
  - **Corroboration rule:** any excluded gap that individually exceeds 1500ms MUST be corroborated before being excluded, confirming the caller was genuinely speaking during that interval rather than the AI silently stalling — otherwise the call is marked NOT PASSED. (Excluded gaps ≤1500ms need no corroboration, since they couldn't have failed the threshold regardless.) This closes the failure mode where a genuine mid-response stall — by construction one of the largest gaps in the call — could otherwise be swept into the excluded set purely for being large.
  - **Corroboration mechanism:** the tester's manual timing log, zeroed to hearing the AI's greeting begin (the same real-world moment as the first `chunk_forwarded_to_twilio` event, offset by the same constant — not zero — transit delay that cancels in relative comparisons). The tester logs elapsed time at which they begin speaking each subsequent scripted turn. A candidate excluded gap is corroborated if its greeting-relative start offset falls within **±1000ms** of the tester's logged greeting-relative start-time for that turn; outside that window, corroboration fails and the call is NOT PASSED.
  - **Ambiguity rule:** if the T-largest/rest split is itself unclear (a gap near the cutoff is close in magnitude to its neighbors), the reviewer resolves it via the same corroboration, or the call is marked NOT PASSED — never a guess.

**All 3 calls must satisfy both conditions on every turn.** A single violation anywhere falsifies Premise 3 — the response is architectural rework, not a retry. This analysis is done manually against the known call script, per the "Manual on purpose" section of `.claude/architecture/mvp/voice-intake-demo.md` — this is this project's first slice, so that MVP doc (not a cross-slice precedent) is the actual source of the manual-review approach.

**What proves DONE:** the 4 named test names shown passing in the transcript, AND the 3 JSONL + `.turnlog.txt` artifact pairs named explicitly with the audible answer-latency (deciding), bridge-internal JSONL delta (diagnostic), and mid-response-gap numbers read out per call — not a generic "the calls worked."

## Deferred to later slices

Everything in Phase 2's seam (μ-law transcoding, streaming resampling, timing recording, frame-error resilience) stays in scope for THIS slice because it's structurally required just to attempt the Exit-criterion measurement — none of it is deferrable without abandoning the slice's own goal.

1. **Caller-type routing / state machine.** Gain: spike stays minimal, isolates "is the bridge fast enough" from "is the routing logic correct." Cost to next slice: designs routing as a new seam on top of an already-proven bridge. Revisit trigger: immediately once this slice's exit criterion passes.

2. **Compliance regex guardrail.** Gain: no need to design the interception hook before knowing whether real-time interception is latency-compatible with a still-unproven gap budget. Cost to next slice: integrates the guardrail without prior evidence of its latency cost. Revisit trigger: immediately once this slice's exit criterion passes (mirrors item 1) — need not wait on the routing slice specifically.

3. **Disclosure opening line (production version).** Gain: decouples the disclosure-content decision from the latency-proof decision — this slice's proactive greeting is minimal, not the real line. Cost to next slice: the real line is very likely longer, so its spoken duration must be re-measured against the same thresholds — the numbers proven here do not automatically transfer. Revisit trigger: the moment the real disclosure line is scripted, before it ships — re-run the same 3-call smoke test with it substituted in.

4. **Post-call dispatcher (transcript storage, single SMS, email brief).** Gain: no dispatch logic needed for this slice's outputs. Cost to next slice: builds storage/SMS/email on top of a flow proven to hold a conversation but never proven to close one out. Revisit trigger: whenever the flow first needs caller-facing side effects for a real broker or demo caller — the Phase 4 test calls (this slice's own spike verification) don't count, since they're internal scripted calls, not the product being demoed to a prospect.

5. **Calendly booking integration.** Gain: no dependency during the latency spike. Cost to next slice: minimal — off-the-shelf, no code, per the MVP doc. Revisit trigger: same as item 4.

6. **UK-region storage policy for production transcripts/audio.** Gain: this slice's spike artifacts are internal test data — `TimingRecorder`'s JSONL contains only event names and timestamps, no phone numbers, transcript text, or audio content — so residency doesn't apply yet. Cost to next slice: must make this "hard to undo" decision before any real caller's transcript/audio is ever written anywhere. Revisit trigger: the first slice that stores a real caller's (not a scripted test call's) transcript or audio — decided at that slice's own Phase 1.

**Not deferred — permanently cut:** Lead capture / landing page was loosely described as "deferred" during this slice's Phase 1b framing, but the MVP doc's own Cut list ("no landing page, no pre-call form... would filter out exactly the people the hypothesis needs to reach") makes this a permanent design decision, not a later-slice deferral. No revisit trigger is given because none is intended.

## Critic notes (non-blocking)
- Which caller-side event triggers `push(..., last=True)` on the resamplers (Twilio's stream "stop" event vs Gemini session close) is not yet pinned down — resolve during implementation.
- `InboundResampler`/`OutboundResampler` are structurally identical aside from direction/rate — could collapse into one `Resampler(in_rate, out_rate)` class without adding indirection; a cleanup opportunity, not a requirement.
- Q4's no-op interruption handler implies `GeminiLiveSessionClient` exposes some event/callback surface not yet named in the seam's Dependencies list — name it during implementation.
- Seam 2's boundary-continuity assertion needs a concrete, self-defined comparison (e.g. a max per-sample int16 LSB difference) chosen by the implementer — soxr's docs do not publish a numeric tolerance to cite.
- Seam 1(b)'s "synthetic silence (all-zero bytes)" wording is ambiguous between the μ-law byte 0x00 (which is NOT silence — verified −32124) and all-zero PCM16 samples (true silence, the intended reading) — tighten to "all-zero PCM16 input samples" when writing the test.
- Seam 4 doesn't specify whether its `TimingRecorder` is a real instance with file re-read, or a mock/spy — either is defensible for a handler-level resilience test; Seam 3 itself establishes the real-instance/file-reread discipline as the project's norm.
