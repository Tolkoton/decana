# Slice profile-loader — planning artifact

Driven by feature `vertical-profile-bridge` (`.claude/architecture/feature/vertical-profile-bridge.md`, slice S1). Phase 1 supplied from the feature artifact, not asked.

## Goal
Deliver `src/decana/profile/`: `load_profile(name, root=Path("profiles")) -> Profile`, a frozen dataclass carrying everything vertical-specific (models, phone number, SMS sender id, operator email, allowed outcomes, per-outcome SMS templates with links, and the three prompt texts), validated at load so that a bad profile fails **before** any call is placed — the same fail-early rule the prior slice ratified for the timing directory (Q13). Ship `profiles/mortgage-broker/` and `profiles/eco-consultant/` as valid, loadable directories. Measurable target: both profiles load; every validation failure enumerated in the feature contract raises `ProfileError` naming the offending field/file, with one test per case; `ruff`, `mypy --strict`, `pytest` green. Pure: no network, no env, stdlib `tomllib` only.

## Premise verified
- **`tomllib` is in the standard library on every interpreter the project can run on.** PEP 680 — stdlib since 3.11; project pins `requires-python = ">=3.13"` / `.python-version` = 3.13. Runtime check 2026-08-26 ran on this machine's **system python 3.12.3** (`import tomllib; tomllib.loads('[a]\nb=1')` → `{'a': {'b': 1}}`) — no 3.13 interpreter or `uv` was on PATH in this session, so the project interpreter itself was not exercised; the claim holds for 3.12 and, by PEP 680's monotonic stdlib inclusion, for 3.13. Falsification condition: pinning below 3.11 — would change Q1's dependency choice (would need `tomli`). Status: **verified (docs + 3.12.3 runtime)**.
- No other external system is touched. Filesystem behaviour relied on (`Path.read_text(encoding="utf-8")`, `Path.is_dir()`) is stdlib-documented and exercised by the tests themselves against `tmp_path`.
- Inherited from the feature: `PR-profile-fully-determines-vertical` (unverified; proven at S7 step 7b, not by this slice).

## Out of scope (deliberately)
- Reading env vars / secrets — `Settings.from_env()` is S3's (composition root); this module never touches `os.environ`.
- Rendering SMS templates with runtime values — S5's `dispatch` does `text.format(**links)`; S1 only proves the placeholders are resolvable.
- Authoring the real prompt content — owner's job before S7; S1 ships clearly-marked DRAFT text that is valid.
- Any Gemini/Twilio/SMTP client construction — S2/S4/S5.
- Schema versioning / migration of `profile.toml` — deferred (see Deferred).
- Loading more than one profile per process, or hot-reload — deferred.

## Seam (contract)
- Signature: `load_profile(name: str, root: Path = Path("profiles")) -> Profile`
- Returns: `Profile` (frozen dataclass, `src/decana/profile/model.py`):
  `name: str` (the directory slug passed in — identity), `display_name: str` (from `vertical.name` — human label; Q12), `live_model: str`, `analysis_model: str`, `phone_number: str`, `sms_sender_id: str`, `operator_email: str`, `outcomes: tuple[str, ...]`, `sms: Mapping[str, SmsTemplate]`, `disclosure: str`, `conversation: str`, `analysis: str`; `SmsTemplate` = frozen dataclass `text: str`, `links: Mapping[str, str]`.
- Errors: raises `ProfileError(ValueError)` — one exception type, message always names the offending field (dotted TOML path, e.g. `twilio.phone_number`) or file (`profiles/<name>/disclosure.md`). Never lets `tomllib.TOMLDecodeError`, `KeyError`, `TypeError`, `FileNotFoundError`, `UnicodeDecodeError` escape. First failure wins (no error aggregation). Enumerated causes, each a test case:
  1. `name` is not a plain directory name (contains `/`, `\`, or `..`; equals `.`; or is empty/whitespace)
  2. `root/name` is not a directory
  3. `profile.toml` missing
  4. `profile.toml` is not valid TOML
  5. a required table is missing or is not a table (`vertical`, `gemini`, `twilio`, `operator`, `outcomes`; likewise `sms` and each `[sms.<outcome>]` must be tables if present)
  6. a required key is missing (`vertical.name`, `gemini.live_model`, `gemini.analysis_model`, `twilio.phone_number`, `twilio.sms_sender_id`, `operator.email`, `outcomes.allowed`)
  7. an unknown table or key is present (strict schema — typos fail, they do not silently no-op). **The allow-list, as data:** top-level tables `vertical`, `gemini`, `twilio`, `operator`, `outcomes` (required) and `sms` (optional); keys per fixed table exactly as in item 6; `sms` contains only sub-tables `[sms.<outcome>]`, and inside each of those `text` is the one fixed key — **every other key is an open link entry** (`links`), validated only by items 11–12, never rejected as unknown. Any non-table value directly under `[sms]` (whatever its key) is a case-5 "must be a table" error naming `sms.<key>`, not an unknown-key error — one branch, no name-dependent tiebreak.
  8. a key has the wrong type or is empty: every required scalar (`vertical.name`, `gemini.live_model`, `gemini.analysis_model`, `twilio.phone_number`, `twilio.sms_sender_id`, `operator.email`) must be a non-empty string after `.strip()` **and is stored stripped** (a padded `"  +44… "` reaching Twilio is the late failure the Goal forbids); `outcomes.allowed` must be a list of non-empty strings, each stored stripped; every `[sms.<outcome>]` link value must be a non-empty string, stored stripped (an empty or padded referenced link ships a broken SMS). `SmsTemplate.text` is stored verbatim except that whitespace-only is rejected (item 11) — it is rendered into an SMS body where the author's spacing is intentional
  9. `outcomes.allowed` is empty, has duplicates, or contains `"unclassified"`
  10. an `[sms.<outcome>]` table whose `<outcome>` ∉ `outcomes.allowed`
  11. an `[sms.<outcome>]` table missing `text`, or `text` empty, or a non-string link value
  12. a `{placeholder}` in `text` with no matching link key; a positional `{}`/`{0}`, attribute `{a.b}`, or index `{a[0]}` field; a link key never referenced in `text` (dead link — also an error, so a renamed placeholder cannot silently drop a URL)
  13. a prompt file (`disclosure.md`, `conversation.md`, `analysis.md`) missing, unreadable as UTF-8, or empty/whitespace-only. **Amended 2026-08-26 (owner-ratified, build session — see Q15):** a leading HTML comment block is metadata for whoever opens the file, not content for the caller or the model, and is removed before the emptiness check. So a file holding nothing but a comment is empty and is rejected, naming that file
- Public module surface: `load_profile`, `Profile`, `SmsTemplate`, `ProfileError`, and `SCHEMA: Mapping[str, frozenset[str]]` (the fixed-table allow-list as data; tests parametrize E7 over it).
- Dependencies (injected): none beyond `root: Path` (tests pass `tmp_path`). No clock, no env, no network.
- Does NOT do: env/secrets, template rendering, prompt authorship, client construction, schema migration, multi-profile.

## Decisions (with WHY)
- **Q1: TOML via stdlib `tomllib`; no YAML/JSON.** Owner-ratified in the feature frame (2026-08-26). Rejected: `pyyaml` — steelman: the most familiar config syntax for most readers; rejected: new dependency plus YAML's implicit typing (`no`→false, `1.10`→float) for zero benefit at this size. Rejected: JSON — steelman: universal, strict; rejected: no comments, and the owner edits these by hand.
- **Q2: strict schema — unknown tables/keys are errors, with `sms` as the one open region.** The schema is held as data (a set of allowed keys per fixed table) so the loader can name `twilio.phone_numbr` as unknown; `[sms.<outcome>]` is deliberately open beyond `text` because link keys are per-vertical by design (the whole reason `links: Mapping[str, str]` exists) — corrected in critic round 1, where a literal reading of "unknown table" would have rejected `sms` itself. WHY: the profile is edited by hand; `phone_numbr = "..."` under a permissive loader passes validation and fails on the first real call, which is the exact late failure Q13 (prior slice) exists to prevent. Rejected: ignore unknown keys (forward-compatible) — forward compatibility is worthless with one consumer in the same repo, and it hides typos. Rejected: warn-only — steelman: never blocks a deploy over a cosmetic key; rejected because a warning in a Cloud Run log nobody reads at call time is the same as silence.
- **Q3: placeholders are validated with `string.Formatter().parse()` plus `field_name.isidentifier()`, not a regex.** `.parse()` yields the raw field name (`"0"`, `""`, `"a.b"`, `"a[0]"`) without classifying it — the `isidentifier()` check is what rejects positional/attribute/index fields (critic round 3 note). WHY: `str.format` is what S5 will actually call, so the check must use `str.format`'s own grammar — `{{` escapes, positional fields, `{a.b}`/`{a[0]}` conversions are all cases a `\{(\w+)\}` regex gets wrong in one direction or the other. Rejected: regex — steelman: one line, no import, readable by anyone; rejected: it diverges from the renderer's grammar, so it is wrong in exactly the cases that matter (`{{`, format specs). Rejected: try-render with dummy values at load — proves resolvability but not the "dead link" direction (a link key never used), and produces a rendered string nobody wants.
- **Q4: dead links are errors, not warnings.** WHY: the failure mode is a renamed placeholder silently dropping the Calendly URL from every SMS — A2's whole point — with nothing in any log. Rejected: allow unused links — "harmless extra config" is exactly how that regression hides.
- **Q5: first failure raises; no error aggregation.** WHY: two profile directories, one operator; fail-fast with one precise message is enough and is the smaller implementation. Rejected: collect all errors — steelman: a hand-authored 13-rule file edited for the first time (`eco-consultant`) could take several fail-fix cycles, and one aggregated report would save real minutes; rejected because it roughly doubles the validator's structure (accumulate + continue past partial state) for two files edited by their author, and each message already names the exact field. Revisit trigger: a third vertical, or a non-developer editing profiles.
- **Q6: `ProfileError` subclasses `ValueError`, one type, message carries the location.** WHY: matches `AudioFrameError(ValueError)` in the bridge; callers (only `__main__`) print the message and exit — they never branch on subtype. Rejected: an exception hierarchy per cause — steelman: lets tests assert on type instead of message text; rejected: thirteen classes nobody dispatches on, and tests asserting the message names the field is the stronger check anyway (a blanket `except Exception` re-raise could not produce it).
- **Q7: `root` keeps the contract's default `Path("profiles")` for convenience, but no production call site relies on it.** Corrected in critic round 0: the feature artifact's `main()` was written as `load_profile(settings.profile)` — no root — which silently made the Cloud Run WORKDIR a load-bearing, untested assumption. Fix, threaded up into the feature artifact: `Settings` gains `profiles_root: Path` from env `DECANA_PROFILES_ROOT`, defaulting to `Path(decana.__file__).resolve().parents[2] / "profiles"` (the repo root when installed editable, which is how the Dockerfile will install it) and `__main__` calls `load_profile(settings.profile, root=settings.profiles_root)`. The default on `load_profile` itself stays only so a REPL/`scripts/` user can type `load_profile("mortgage-broker")` from the repo root; tests always pass `tmp_path` or the explicit repo `profiles/` dir. Rejected: drop the default entirely — steelman: makes "no call site depends on CWD" true by construction, not by discipline; rejected because it deviates from the ratified contract signature for no production gain, since production is explicit either way. Rejected: package-relative data via `importlib.resources` — steelman: works from any CWD with zero config; rejected because profiles are owner-edited data that must live outside the wheel and be swappable by directory (A4). Rejected: leave it CWD-relative and document WORKDIR — steelman: zero code; rejected because it is a premise nobody tests and S6 does not exist yet to verify it.
- **Q8: `name` is validated as a bare directory name.** WHY: `name` comes from an env var (`DECANA_PROFILE`); `load_profile("../secrets")` must be a `ProfileError`, not a directory walk. Rejected: trust the caller — steelman: the only caller is our own `__main__` on our own container, and `Path` joining is not a security boundary here; rejected: the value still originates in an env var set by a human, and a one-line check turns a confusing `FileNotFoundError` for `../x` into a `ProfileError` that names the problem.
- **Q9: mutable containers are copied into the frozen dataclass; `Mapping` annotation, plain `dict` storage.** WHY: `frozen=True` prevents attribute rebinding; copying at construction prevents aliasing the parsed TOML dict. Rejected: `types.MappingProxyType` — steelman: true read-only enforcement at runtime, and it compares equal to a dict so tests are unaffected; rejected: `mypy --strict` already types the field as `Mapping` so mutation is a type error at every call site in this repo, and the proxy adds a construction step for a guarantee no caller exercises. Revisit if a caller is ever caught mutating.
- **Q10: prompt texts — `disclosure` is `.strip()`ped, `conversation`/`analysis` are read verbatim.** WHY: `disclosure` goes inside a TwiML `<Say>` where leading/trailing newlines are audible pauses; the other two go to the model as system text where whitespace is harmless and the author's layout is theirs. Emptiness is checked on the stripped text for all three. Rejected: strip all three — steelman: one rule, no special case; rejected because a prompt author's deliberate trailing blank line or leading heading indentation is theirs to keep, and the model does not care. Rejected: strip none — steelman: loader stays a pure reader; rejected because `<Say>\n\nThis is an AI…\n</Say>` audibly pauses before speaking.
- **Q11: shipped profile content is a marked DRAFT, not lorem ipsum.** WHY: the owner has to replace it anyway; a plausible draft (disclosure line, intake conversation, outcome+compliance analysis instructions) gives them something to edit and lets the S2 spike run meaningfully. Every file opens with `<!-- DRAFT — owner to review before S7 -->`. Rejected: pure placeholder — steelman: zero risk of a draft being mistaken for owner-approved compliance wording; rejected because the `<!-- DRAFT -->` header carries that signal explicitly, and lorem ipsum makes the S2 spike and the tracer call meaningless. `eco-consultant` differs from `mortgage-broker` in every field except the two model names (which may legitimately coincide and are excluded from Seam 3's differs-loop) so A4's diff is real.
  **Amended 2026-08-26 (owner-ratified, build session): the marker is file metadata, and the loader strips it (Q15).** As first ratified, Q11 and P5 together were a defect, demonstrated by the smoke run: `profile.disclosure` is spoken verbatim by Twilio `<Say>` (feature contract, S3 guarantee (c)), so the marker became the first thing the caller heard, and the first line of the model's system instruction. The damage was not the draft text — it was that P5 made the marker *permanent*, so a real compliance disclosure authored before S7 would still have been read out with an HTML comment in front of it. Fixed by removing the marker at load (Seam item 13, Q15) rather than by removing it from the files: it must stay visible to whoever opens `disclosure.md`, since that is the compliance text and mistaking a draft for approved wording is exactly what Q11 exists to prevent. Rejected: leave as ratified — steelman: it is draft content the owner replaces before S7 anyway, and A3's latency is measured to the START of `<Say>`, so the metric is untouched; rejected because P5 keeps the marker after the text is replaced, moving the same decision to a worse moment. Rejected: move the marker to `profile.toml`'s comment header or a per-profile README, narrowing P5 — steelman: no loader change at all; rejected because a reader opening `disclosure.md` alone would then see no warning on the one file where it matters most.
- **Q12: two names, two fields — `Profile.name` is the directory slug, `Profile.display_name` is `vertical.name`.** Raised in critic round 2: the seam had one `name` slot fed by two sources. `name` is identity — it comes from the `load_profile` argument (ultimately `DECANA_PROFILE`), it is what A4's `git diff` and the artifact filenames key on, and it is machine-safe (bare directory name, Q8). `vertical.name` is a human label ("UK mortgage broker intake") for operator-facing text; it is required (an empty label in an email subject is a silent quality bug) but never used as an identifier. No cross-check between them: they are different things and disagreement is not an error. S5's email subject uses `display_name`; contract amended. Rejected: cross-validate `vertical.name == directory` — steelman: catches a copy-pasted `[vertical]` block in `eco-consultant`; rejected because it forces the human label to be a slug, and the copy-paste risk is already caught by Seam 3's "every scalar differs between the two shipped profiles" assertion. Rejected: drop `vertical.name` and derive the label from the slug — steelman: one less required key; rejected because `mortgage-broker` is not what an operator wants to read in a subject line.

- **Q13 (build-time, decided alone 2026-08-26): `SCHEMA` lives in `load.py`, not `model.py`.** The Seam names `SCHEMA` in the public surface without placing it; the feature contract places `ProfileError` and `load_profile` in `load.py` and the two dataclasses in `model.py`. `SCHEMA` is a validation input, not a value object, so it sits with the validator. Reversible in one commit; overrule if you disagree.
- **Q14 (build-time, decided alone 2026-08-26): `src/decana/profile/__init__.py` stays empty; consumers import from `decana.profile.load` / `decana.profile.model`.** Follows the repo's existing precedent — `src/decana/bridge/__init__.py` is empty and every test imports `from decana.bridge.codec import …`. "Public module surface" in the Seam means which names are public, not that they are re-exported at the package root. Reversible in one commit; overrule if you disagree.

- **Q15 (build-time, ESCALATED and owner-ratified 2026-08-26): a leading HTML comment block is stripped from each prompt file at load.** Raised by the slice-builder against ratified text, not decided alone: it amends Q11 and Seam item 13, and adds ids to the exit criterion's required-node set — two entries on the never-decide-alone list. Evidence it was real, not theoretical: `scripts/smoke_profile.py` printed `<!-- DRAFT — owner to review before S7 -->` as the first line of all three prompts for both shipped profiles. Applied uniformly to all three files rather than to `disclosure.md` alone — one rule, and the marker is noise in a system instruction even where it is not audible. Order inside `_read_prompt` is load-bearing: **strip the comment, then check emptiness, then apply Q10's whitespace policy** — checking emptiness first would let a comment-only file through as `""`. Rejected: strip only `disclosure.md` — steelman: the minimum change, and only that file is spoken; rejected because two rules where one suffices, and the model gains nothing from reading a review marker. Rejected: strip HTML comments anywhere in the file — steelman: catches a marker someone puts on line 2; rejected because prompt bodies are prose the author owns, and silently deleting from the middle of one is a worse failure than not deleting from the top. Accepted risk recorded as W-2.

## Hardest seams (test-confidence points — distinct from the contract Seam above)
- **Seam 1: placeholder grammar is `str.format`'s grammar, not a regex** — test approach: a parametrized test over `SmsTemplate.text` values where a naive `\{(\w+)\}` regex and `string.Formatter().parse()` disagree: `"{{calendly_url}} details at {booking_url}"` (escaped braces must NOT be a placeholder — the escaped token is deliberately a plausible field name so a naive `\{(\w+)\}` regex extracts `['calendly_url', 'booking_url']` while the parser yields `['booking_url']`; measured in critic round 0, where the earlier example `{{literal braces}}` failed to discriminate because `\w+` cannot span a space), `"{0}"` and `"{}"` (positional → `ProfileError`), `"{calendly_url.host}"` and `"{links[0]}"` (attribute/index → `ProfileError`), `"{calendly_url:>10}"` (format spec allowed, field name is still `calendly_url`), `"{calendly_url!r}"` (conversion allowed), and an unbalanced `"{calendly_url"` (`ValueError` from the parser → translated to `ProfileError` naming `sms.new_client.text`). The passing cases assert the exact set of extracted field names, so a regex/substring implementation is caught by the `{{calendly_url}}` case (extra field) and by the unbalanced case (no error). The test module carries the naive regex as a named helper `_naive_regex_fields()` and one test asserts, for the escaped case, that `_naive_regex_fields(text) != extracted_fields(text)` — so if someone later "simplifies" the test string, the discrimination property itself fails rather than silently vanishing. Rules out: substring checks and regex checks. ("Try `.format()` with dummies" — which accepts a dead link — is ruled out by Seam 2's case-12 unused-link mutation, not by this seam's text cases.)
- **Seam 2: every failure path is translated, and the message names the location** — test approach: one known-good profile written to `tmp_path` by a fixture builder, then a parametrized test with at least one *mutation* per enumerated Seam cause 1–13, mapped explicitly (case → mutation): 1 → `name="../x"`, `name=".."` (bare), `name="."` (bare dot — `root / "."` normalises to `root` itself, so without this ban it would fall through to a case-3 "profile.toml missing" and the loader would be searching `root` for a profile; critic round 13 verified with pathlib), `name="sub/dir"` (bare forward slash), `name="a\\b"` (isolated backslash) and `name=""`; 2 → `name="nonexistent"` and `name` pointing at a regular file, not a directory; 3 → delete `profile.toml`; 4 → write `"not = = toml"` into it AND, as a separate row, write invalid UTF-8 bytes (`b"\xff\xfe[vertical]"`) into it — `UnicodeDecodeError` from the TOML *read* is a different exception from `TOMLDecodeError`, and the same exception type as case 13's prompt-file read but at a different call site — so the loader needs two catch sites, each naming its own file (critic rounds 2 and 5, verified by running both read strategies); 5 → delete `[twilio]`, AND `vertical = "not a table"` (required table present as a scalar — `tomllib` parses it, `data["vertical"]["name"]` raises `TypeError`, which the allow-list diff on `data.keys()` cannot see; the loader must `isinstance(..., dict)`-check each table before descending — critic round 8), AND `sms = "x"` / `[sms] new_client = "x"` (the open region's sub-tables must also be dicts); 6 → one row per required key (all seven), e.g. delete `phone_number`; 7 → an unknown key in EVERY fixed table, parametrized over the loader's own `SCHEMA` mapping (`for table in SCHEMA: add f"{table}.extra"`) rather than a hand-picked `twilio.phone_numbr` — so a per-table copy-paste bug in any of the five is caught and a table added to `SCHEMA` later is tested automatically (critic round 12); (a scalar under `[sms]` is E5, not E7); 8 → `phone_number = 44`, and one row per required scalar set to `""` or `"  "` (`vertical.name`, `gemini.live_model`, `gemini.analysis_model`, `twilio.phone_number`, `twilio.sms_sender_id`, `operator.email` — a type-only `isinstance(str)` validator passes all six and ships `Profile(phone_number="")`, the exact late failure the Goal forbids; critic round 9), and `calendly_url = ""` (empty referenced link), `allowed = "x"` and `allowed = {}` (non-list), `allowed = ["a", 1]`, and `allowed = ["a", ""]` plus `allowed = ["a", "  "]` (empty/whitespace-only element — a type-only `isinstance(o, str)` check passes these and admits an outcome named `""`, which then makes `[sms.""]` addressable; critic round 5); 9 → `allowed = []`, `allowed = ["a","a"]`, `allowed = ["a","unclassified"]`; 7 (cont.) → add a wholly unknown top-level `[bogus]` table (a validator that walks only the five known names admits it; the allow-list must be diffed against `data.keys()`); 10 → add `[sms.bogus]`; 11 → drop `text`, `text = ""`, `text = 3` (the `[sms.<outcome>]` path is separate from the fixed tables, and a `not text` truthiness check passes `3` — critic round 6), `calendly_url = 3`; 12 → `{missing}`, unused link key (the `{0}`/`{a.b}`/`{a[0]}` raise sites are Seam 1's G2–G5 rows, which go through `load_profile()`); 13 → delete `analysis.md`, invalid UTF-8 bytes in `conversation.md`, `"   \n"` in `disclosure.md`. (Twenty-odd parametrized rows; the docstring of each names its Seam cause number so coverage of 1–13 is checkable by reading the file.) Each asserts `type(exc) is ProfileError` (exact type, not `isinstance`) AND that the message contains the specific dotted field path or file name for that case — for cases 1–2, which precede any parse, the message names the offending `name` value (case 1) or the missing directory path (case 2). Each mutation is single-fault against a known-good profile; which error wins when a profile has several faults at once is implementation-order-determined and deliberately unspecified (Q5), so reordering checks in a refactor is not a regression. Rules out: a blanket `except Exception as e: raise ProfileError(str(e))` at the top — it would pass an `isinstance` check but cannot name `twilio.phone_number` for a `KeyError('phone_number')`, and it would turn a programmer bug in the loader into a "profile error". Also rules out: `dict.get(..., default)` silently tolerating a missing key (case 6) or an unknown key (case 7).
- **Seam 3: the shipped profile directories are validated by the same loader, not by hand** — test approach: `test_shipped_profiles_load` calls `load_profile(name, root=REPO_ROOT / "profiles")` for both `mortgage-broker` and `eco-consultant` (path derived from `__file__`, not CWD), asserts each loads, and asserts every field (scalars, and the `outcomes` tuple and `sms` mapping too — inequality is well-defined for both) differs between the two — the full list, so the assertion is written as a loop over `dataclasses.fields(Profile)` minus `name`/`live_model`/`analysis_model` (the two model names are legitimately shared across verticals) plus the SMS link URLs; `display_name`, `phone_number`, `sms_sender_id`, `operator_email`, `disclosure`, `conversation`, `analysis` are therefore all covered without being enumerated by hand. Separately, for each shipped profile: `profile.name == <the literal argument>` and `profile.display_name != profile.name` — the Q12 regression test: a loader that derives `name` from `vertical.name` (the conflation corrected in Phase 2 round 2) still yields two *different* names across the two profiles and so passes the differs-loop; only the equality against the argument catches it (critic round 7) so A4's diff is guaranteed non-trivial. Also asserts `set(eco.sms) < set(eco.outcomes)` (strict subset — eco defines a template for only some outcomes) and `set(broker.sms) == {"new_client"}`, so the shipped data exercises `sms` optionality. Rules out: synthetic-fixture-only tests that let the real directories drift into invalidity, and a lazy `eco-consultant` that is a copy of the broker profile with one word changed. Also asserts (P5) that every shipped `.md` opens with `<!-- DRAFT — owner to review before S7 -->` (Q11), so the DRAFT marker is test-backed rather than eyeballed; wrong implementation ruled out: shipping un-marked draft prose that a later reader takes for owner-approved compliance wording.
  **Positive cases in the same file (critic round 11):** `test_sms_is_optional` — a profile with no `[sms]` table at all loads with `profile.sms == {}`; and a profile whose `outcomes.allowed` has three entries but only one `[sms.<outcome>]` table loads with exactly that one key in `profile.sms`. Wrong implementation this rules out: a validator that reads item 5's parenthetical as "sms required" or demands full outcome coverage — it passes every failure-direction row and silently breaks A2's "no SMS unless the profile defines a template" the first time a vertical omits one. To make sure the shipped profiles exercise this path too, `eco-consultant` deliberately defines a template for only a subset of its outcomes (Seam 3 asserts that). Also: case 6 is one row per required key (all seven), and case 8 includes `allowed = "x"` / `allowed = {}` (non-list); `name="."` is banned at case 1 (see that row).
  **Callout within Seam 2 (was a separate Seam 4; folded per critic round 1):** cases 6 and 7 are opposite failure directions. A loader that validates *required* keys by lookup passes every "missing" test and silently accepts `phone_numbr`; the unknown-key mutation asserts the message names `twilio.phone_numbr`, which forces the schema to be held as data (allowed keys per table) rather than as a sequence of lookups. Verified: TOML itself accepts a scalar under `[sms]`, so the loader must walk `sms.items()` and type-check each value.
- **Seam 4: the frozen dataclass does not alias the parsed TOML** — test approach: `test_profile_does_not_alias_parsed_toml` loads a profile, then mutates the *source* it was built from and asserts the `Profile` is unchanged — concretely, the test monkeypatches `tomllib.load`/`loads` (or an equivalent spy — no test-only production seam is required) to capture the parsed dict, load, then `captured["sms"]["new_client"]["calendly_url"] = "hacked"` and assert `profile.sms["new_client"].links["calendly_url"]` still holds the original; plus the direct identity check `profile.sms is not captured["sms"]` and `profile.outcomes` is a `tuple` (not the parsed list). Wrong implementation this rules out: building each `SmsTemplate(text=item.pop("text"), links=item)` — `links` aliases the parsed sub-dict (mypy accepts it: the TOML value is `Any`) — and `outcomes=parsed["outcomes"]["allowed"]` stored as the parsed list. It passes Seams 1–3 untouched (critic round 1 checked each) because none of them mutate after construction, yet it means `frozen=True` is a lie: any caller holding the parsed dict (or a later "reload" feature) can change a live profile's SMS links without a trace. `FrozenInstanceError` on attribute assignment is asserted in the same test as the cheap half of the invariant. **Hashability is a documented non-feature (critic round 4, verified by execution):** because `sms`/`links` are dict-backed, `hash(profile)` raises `TypeError: unhashable type: 'dict'` and neither `mypy --strict` nor `ruff` will ever say so; the same test asserts `pytest.raises(TypeError): hash(profile)` so a future `@lru_cache`/`set` user (S2–S5 all consume this type) finds an explicit test, not a landmine. Q9's rationale covers this: read-only enforcement and hashability are both "no caller exercises it today" — revisit both together if one ever does (`MappingProxyType` alone would not restore hashability; that needs tuple-of-pairs storage).
- **Seam 5: the whitespace policy is observable in what is STORED, not just in what is rejected** — test approach: `test_prompt_whitespace_policy` writes all three `.md` files with identical leading/trailing whitespace (`"\n\n  TEXT  \n\n"`) and asserts `profile.disclosure == "TEXT"` while `profile.conversation` and `profile.analysis` equal the raw file content byte-for-byte; and `test_scalar_whitespace_policy` (parametrized over the six required scalars, each outcome, and each link value) writes `"  VALUE  "` and asserts the stored field equals `"VALUE"`, while `SmsTemplate.text = "  Hi {calendly_url}  "` is stored verbatim. Wrong implementation this rules out (critic round 10): validate-on-stripped, store-raw — every rejection test still passes, and a padded phone number reaches Twilio. Wrong implementations this rules out (critic round 3 verified each passes Seams 1–4): strip all three (a trailing blank line an author uses to separate sections disappears), strip none (`<Say>` audibly pauses before the disclosure), and strip the wrong one. Emptiness (case 13) is separately asserted on whitespace-only content for each of the three files, so "empty after strip" and "stored stripped" are two assertions, not one.

### Ratified behavior list (the test plan)

**Mapping rule, uniform for all five seams:** one id ↔ one *test node* as pytest reports it. A plain function carries exactly one id, as the first token of its docstring (`"""E3: …"""`). A parametrized function carries one id per row via `pytest.param(..., id="G1")`, and its docstring opens with the id *range* it spans (`"""G1–G8: …"""`); each row's own id is the checkable unit. So "every id has a test" is verified against `pytest --collect-only -q` node ids plus docstrings, not docstrings alone; and "no test carries no id" means every collected node id ends in `[G1]`-style or belongs to a function whose docstring opens with a single id. Consequences: G1–G8 is one parametrized function with eight `pytest.param` ids; E-cases are parametrized with **one row id per enumerated mutation**, and the closed set of row ids is ratified below — every listed row id must be a collected, passing node; the cause prefix is a grouping, not the unit of proof (Q21 rejected prefix-as-proof); W1–W8 are eight separate functions (W7/W8 added 2026-08-26 by Q15) (each may loop internally over its fields — W3 over six scalars — since the id is the behavior, not the field) (the earlier `test_prompt_whitespace_policy`/`test_scalar_whitespace_policy` names are split); V1–V4 and P1–P5 are separate functions.

**Seam 1 — placeholder grammar (G) — every G case is an integration test: it writes a full profile to `tmp_path` with the given string as `[sms.new_client] text` and calls `load_profile()`, asserting either the loaded `SmsTemplate` or a `ProfileError` naming `sms.new_client.text`. No bare-helper tests; the grammar check is proven through the real entry point:** G1 `{{calendly_url}} details at {booking_url}` → fields `{booking_url}` only, and `_naive_regex_fields(text) != extracted_fields(text)`; G2 `{0}` → ProfileError; G3 `{}` → ProfileError; G4 `{calendly_url.host}` → ProfileError; G5 `{links[0]}` → ProfileError; G6 `{calendly_url:>10}` → field `calendly_url`, accepted; G7 `{calendly_url!r}` → field `calendly_url`, accepted; G8 unbalanced `{calendly_url` → ProfileError naming `sms.<outcome>.text`.
